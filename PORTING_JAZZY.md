# Porting from ROS 2 Humble to ROS 2 Jazzy

Branch `tesi-davide` of the fork `Davide-Colabella/nereo_ros2_code`, from `main` of `PoliTOcean/nereo_ros2_code` (a4556e6). Target: Ubuntu 24.04 (noble) with ROS 2 Jazzy on both the Raspberry Pi and the workstation (the Pi already ran Jazzy, see `SETUP_RPI/README.md`). Changes are kept minimal: only what does not build, does not run or names the wrong distro.

## How it was checked

The apt repository of ROS was not reachable from the build machine, so Jazzy came from [RoboStack](https://robostack.github.io/) (`robostack-jazzy` conda channel: `ros-jazzy-ros-base` plus `tf2_ros`, `tf2_geometry_msgs`, `rosbridge_server`, `joy`, `tf_transformations`, `ament_lint_*`, `eigen`). RoboStack ships newer Python tooling and libraries than Ubuntu 24.04 apt (setuptools 79, Eigen 5.0); the notes below say where a change matters only there.

| Workspace | `colcon build` | `colcon test` |
|---|---|---|
| `gui_ws` (`nereo_interfaces`, `gui_pkg`, `joystick_pkg`, `web_pkg`) | ok | `joystick_pkg`: 3 lint tests run; `test_flake8` and `test_pep257` fail on existing style issues in `joy_to_cmdvel.py` (import order, docstrings), `test_copyright` skipped. Not porting issues, left as they are. The other packages have no tests |
| `rpi_ws` (`nereo_sensors_pkg`, `sonar_pkg`) | ok (only the existing `-Wsign-compare`, `-Wunused-function` warnings in the sensor C sources) | 11/11 |
| `ros2_controller_tuning_aid` (separate repository, fork `Davide-Colabella/ros2_controller_tuning_aid`, same branch name) | ok after the Eigen change below | no tests registered in CMake |

Every node was also started for 6 s with `ros2 run` and stopped with SIGINT: `safety_node`, `web_server_node` (twice on the same port), `joy_to_cmdvel`, `rov_cmd_monitor`, `rov_sim_node`, `sonar_sim_node`, `nereo_controller_node`; all exit cleanly, with no tracebacks. `gui_node` and `sonar_node` were only imported, because they need a display and the Ping1D serial port. `nereo_sensors_pkg` was only built and unit-tested, because it needs the I2C sensors.

## Changes

| File | Why | API difference |
|---|---|---|
| `gui_ws/src/{gui_pkg,joystick_pkg,web_pkg}/setup.py`, `rpi_ws/src/sonar_pkg/setup.py` | With recent setuptools `tests_require` is ignored (`Unknown distribution option: 'tests_require'`), so colcon does not find pytest and runs 0 tests | `tests_require=['pytest']` → `extras_require={'test': ['pytest']}`, the form generated by `ros2 pkg create` on Jazzy. Needed with setuptools ≥ 72 (RoboStack); with Ubuntu 24.04's setuptools 68 the old key is only deprecated. Works on both |
| `gui_ws/src/joystick_pkg/package.xml` | `ros-humble-joy` is a Debian package name, not a rosdep key: `rosdep install` cannot resolve it on any distro, and it pins Humble | `<exec_depend>ros-humble-joy</exec_depend>` → `<exec_depend>joy</exec_depend>` |
| `gui_node.py`, `rov_sim_node.py`, `joy_to_cmdvel.py`, `rov_cmd_monitor.py`, `safety_node.py`, `sonar_node.py`, `sonar_sim_node.py` | On Jazzy `rclpy.init()` installs a SIGINT handler that already shuts the context down; the `rclpy.shutdown()` in `finally` then raises `RCLError: rcl_shutdown already called` on every Ctrl-C | `rclpy.shutdown()` → `rclpy.try_shutdown()` (no-op if already shut down; available since Humble). `web_server_node.py` already wrapped the call in `try/except` and is unchanged |
| `gui_ws/src/web_pkg/web_pkg/web_server_node.py` | On SIGINT the node never exited and kept port 8080 bound (a second start failed with `Address already in use`): it replaced rclpy's SIGINT/SIGTERM handlers with a Python one, so on Jazzy `rclpy.spin()` stayed blocked in its wait set and the Python handler never got to run | Custom `signal.signal(...)` handlers removed; rclpy's own handler makes `spin()` raise `KeyboardInterrupt`, the existing `finally` and `atexit` release the port. Checked: exits on SIGINT and restarts on the same port |
| `ros2_controller_tuning_aid/src/nereo_controller_node/CMakeLists.txt` | `fatal error: Eigen/Geometry: No such file or directory`: Eigen 5 no longer defines `EIGEN3_INCLUDE_DIR`/`EIGEN3_LIBRARIES`, so the include path was empty | `include_directories(${EIGEN3_INCLUDE_DIR})` + `target_link_libraries(... ${EIGEN3_LIBRARIES})` → `target_link_libraries(nereo_controller_node Eigen3::Eigen)`. Not a Jazzy change: with Ubuntu 24.04's Eigen 3.4 the old variables still exist, but the imported target works with both |
| `ros2_controller_tuning_aid/.../scripts/pid_tuner_gui.py` | Same SIGINT/shutdown issue | `rclpy.try_shutdown()` |
| `README.md`, `SETUP_RPI/README.md`, `ros2_controller_tuning_aid/README.md` | Said Humble | Jazzy, `ros-jazzy-*` packages |
| `SETUP_RPI/setup_rpi.sh`, `gui_start.sh` | Installed and sourced `ros-humble-ros-base` | `ros-jazzy-ros-base`, `/opt/ros/jazzy/setup.bash`. `ros-humble-*` does not exist on Ubuntu 24.04, so the Pi script could not work as it was |

## Not changed, to know

- **Workstation OS:** Jazzy needs Ubuntu 24.04. `gui_start.sh` installs from the apt repository of the running Ubuntu release, so on a 22.04 workstation it would now fail: the workstation has to move to 24.04 first.
- **ROS apt key:** `setup_rpi.sh` and `gui_start.sh` still add the ROS apt key by downloading `ros.key`. The current official procedure installs the `ros2-apt-source` package instead (see the ROS 2 Jazzy installation guide); worth switching when the scripts are next touched.
- **Python dependencies:** PyQt6 and `bluerobotics-ping` are still installed with pip (`rosdep.yaml`), unchanged.
- **Interface hashes:** Jazzy adds type hashes to the middleware; Humble and Jazzy nodes talking to each other is not supported. Everything has to run Jazzy.
